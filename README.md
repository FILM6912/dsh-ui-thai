# DSH UI Thai

บันเดิลภาษาไทยพร้อมเสียงพูดสำหรับ **DeepSeek Harness 0.2.2-rc.3** เพิ่ม **ไทย** ผ่านระบบ locale เดิม และรวม dsh-voice รุ่นปรับแต่งทั้ง backend และ UI ในแพ็กเดียว ไม่ต้องติดตั้งปลั๊กอินเสียงแยก ส่วนคำแปลไม่ส่งข้อมูลออกเครือข่าย แต่การถอดเสียงจะส่งเสียงไปยังผู้ให้บริการที่ตั้งค่าไว้ (รวมคลาวด์หากเลือกใช้)

**3,965 คีย์ ใน 68 หมวดภาษา** ตามชุดต้นฉบับที่ตรวจสอบไว้ ไม่ใช่การรับรองว่าทุกส่วนของแอปและปลั๊กอินภายนอกเป็นภาษาไทยแล้ว

## วิธีติดตั้ง

### ติดตั้งด้วยชื่อแพ็กเกจ

รุ่น **1.2.0** รวมระบบเสียงในแพ็กเดียว ดูรุ่นที่เผยแพร่ล่าสุดได้ที่ [npm](https://www.npmjs.com/package/dsh-ui-thai) และตรวจด้วย `npm view dsh-ui-thai version` ก่อนอัปเดต รายการเปลี่ยนแปลงอยู่ใน [CHANGELOG.md](<CHANGELOG.md>)

ติดตั้งผ่าน npm registry ด้วยคำสั่งนี้ รองรับ DSH **0.2.2-rc.3**

```sh
dsh plugin --profile <your-profile> add dsh-ui-thai
```

แทน `<your-profile>` ด้วยชื่อโปรไฟล์ที่คุณใช้ โดยไม่ใส่เครื่องหมาย `<` และ `>` แล้วเลือก **Settings → General → Language → ไทย** หากระบบขอให้เริ่มใหม่ ให้ทำตามข้อความนั้น ขั้นตอนเผยแพร่สำหรับผู้ดูแลอยู่ใน [PUBLISHING.md](<PUBLISHING.md>)

อีกทางเลือกหนึ่งคือใช้ GitHub package spec แทนชื่อ npm

```sh
dsh plugin --profile <your-profile> add github:FILM6912/dsh-ui-thai
```

ตรวจสอบรูปแบบ CLI แล้ว แต่ยังไม่ได้ทดสอบการติดตั้งผ่าน GitHub package spec แบบครบวงจร วิธีติดตั้งจากโฟลเดอร์ด้านล่างเป็นทางเลือก

### ย้ายจากแพ็กเกจชื่อเดิม

หากเคยติดตั้ง `@local/dsh-thai` ให้ถอนบันเดิลเดิมใน **Plugins** ก่อนติดตั้ง `dsh-ui-thai` และทำตามคำขอเริ่มแอปใหม่ อย่าเปิดสองแพ็กเกจพร้อมกัน เพราะทั้งคู่ลงทะเบียนภาษา `th` เหมือนกัน รุ่นเตรียม npm นี้ไม่ได้เปลี่ยนแพ็กเกจที่ติดตั้งในเครื่องเดิมโดยอัตโนมัติ

### 1. ดาวน์โหลดปลั๊กอิน

ใช้ Git ใน Terminal หรือ PowerShell

```sh
git clone https://github.com/FILM6912/dsh-ui-thai.git
```

หรือกด **Code → Download ZIP** บน GitHub แล้วแตก ZIP ก่อนติดตั้ง

ไม่ต้องรัน `npm install` หรือ build เพื่อใช้งาน มี [bundle-client.js](<bundle-client.js>) และ backend ใน [vendor/dsh-voice](<vendor/dsh-voice/>) พร้อมแล้ว ใช้บริการ DSH และ shared runtime ของรุ่นที่ระบุ ไม่ติดตั้ง React หรือ DSH ซ้ำ แพ็กนี้ไม่ได้แถมโมเดลถอดเสียง, ffmpeg หรือ API key ให้ตั้งผู้ให้บริการในหน้า Voice ตามเดิม

### 2. ติดตั้งใน DeepSeek Harness

1. เปิด **Plugins → Add plugin**
2. เลือกติดตั้งจากไดเรกทอรีในเครื่อง
3. เลือกโฟลเดอร์ที่ clone หรือแตก ZIP ซึ่งมี [package.json](<package.json>) อยู่โดยตรง ไม่เลือกโฟลเดอร์แม่
4. ตรวจว่าปลั๊กอิน **Thai language pack / ชุดภาษาไทย** เปิดใช้งานแล้ว

หากต้องการให้เอเจนต์ติดตั้ง ให้ใช้โหมดที่มีเครื่องมือจัดการปลั๊กอิน แล้วส่งคำขอนี้โดยแทนที่พาธให้ตรงกับเครื่องของคุณ

```text
ติดตั้งและเปิดใช้บันเดิล DSH จากโฟลเดอร์ <พาธเต็มของโฟลเดอร์ dsh-ui-thai> ด้วย plugin_manager แล้วรายงานผลการติดตั้ง
```

ชื่อบันเดิลภายในและชื่อแพ็กเกจสำหรับ npm คือ `dsh-ui-thai` โดยการติดตั้งต้องผ่านโปรไฟล์ DSH ไม่ใช่ `npm install` ในโฟลเดอร์โครงการทั่วไป

### 3. เลือกภาษาไทย

เปิด **Settings → General → Language → ไทย**

หากยังไม่เห็นตัวเลือก ให้รีเฟรชหน้า หากระบบแจ้งว่าต้องเริ่มใหม่ ให้เริ่ม DeepSeek Harness ใหม่ตามข้อความนั้น ปลั๊กอินไม่บังคับเปลี่ยนภาษาที่คุณเลือกไว้

> รองรับเฉพาะ DSH **0.2.2-rc.3** ตาม `engines.dsh` หากเวอร์ชันไม่ตรง ตัวจัดการปลั๊กอินอาจปฏิเสธการติดตั้ง ไม่ควรข้ามการตรวจเวอร์ชันโดยไม่ได้ทดสอบความเข้ากันได้

## อัปเดตและถอนการติดตั้ง

หากติดตั้งจาก Git ให้รันในโฟลเดอร์ปลั๊กอิน

```sh
git pull --ff-only
```

จากนั้นติดตั้งจากโฟลเดอร์เดิมผ่านตัวจัดการปลั๊กอินอีกครั้ง และทำตามผลลัพธ์เรื่องการเริ่มแอปใหม่ การแก้ไฟล์อย่างเดียวไม่รับประกันว่าหน้าเดิมจะโหลดโค้ดใหม่แล้ว อย่าลบหรือย้ายโฟลเดอร์ที่ติดตั้งไว้ เพราะการติดตั้งจากไดเรกทอรีอาจเชื่อมโยงกับโฟลเดอร์นี้

ถอนการติดตั้งได้ใน **Plugins** โดยเลือกชุดภาษาไทยแล้วปิดใช้งานหรือถอนการติดตั้ง เมื่อปลั๊กอินถูกถอน ภาษาไทยจะถูกนำออกจากรายการและ DSH จะใช้ภาษาสำรองที่พร้อมใช้งาน

## ระบบเสียงในแพ็กเดียว

- ไม่ต้องติดตั้ง `@goodandready/dsh-voice` แยก โค้ด Host และ Client รวมอยู่ในบันเดิล `dsh-ui-thai`
- **ย้ายจากรุ่นแยก:** ปิดบันเดิล `@goodandready/dsh-voice` ใน Plugins ก่อนติดตั้งรุ่นนี้ ไม่ต้องลบข้อมูลหรือ API keys แพตช์มีตัวปิดแถวชื่อมาตรฐาน `dsh-voice` อีกชั้น หากคุณเปลี่ยนชื่อแถวเองต้องปิดด้วยตนเอง ห้ามเปิดสอง backend พร้อมกัน
- เก็บ namespace เสียง/locale/API `dsh-voice`, เส้นทาง API และชื่อ credential เดิม แต่ DSH รุ่นนี้เก็บ Settings ตาม **entry id**: รุ่นรวมเก็บใน `local-dsh-thai` ผ่าน adapter จึงต้องย้าย config เดิมครั้งเดียวก่อนใช้งาน อย่าถือว่าเพียงเก็บชื่อ namespace แล้วค่าจะย้ายเอง
- **ย้ายการตั้งค่า:** ก่อนปิด standalone ให้บันทึก config จากหน้า Voice หรือ API `/dsh-voice/config` ไปยังไฟล์ส่วนตัวที่ปลอดภัย (อาจมีข้อมูลลับ ห้าม commit/ส่งในแชต) เมื่อติดตั้งรุ่นรวมและเริ่มแอปใหม่แล้ว ให้นำค่าเดิมกลับผ่านหน้า Voice หรือ PUT endpoint เดิมพร้อม revision ปัจจุบัน ตรวจปุ่ม Alt/provider แล้วลบสำเนาเมื่อไม่ต้องการ ไม่ต้องสร้าง API key ใหม่ รุ่นรวมไม่ลบข้อมูลของแถวเดิมเพื่อให้ย้อนกลับได้
- ค่าเริ่มต้นแสดง **2 ปุ่ม**: ไมค์พิมพ์ด้วยเสียงอยู่ทางซ้าย และ **คุยต่อเนื่อง** อยู่ขวาสุด ปุ่มข้อความเสียงและเลือกโหมดซ่อนไว้ก่อน แต่เปิดกลับได้ในตั้งค่า
- เปิด **คุยต่อเนื่อง** เพื่อฟัง → หยุดพูด → นับถอยหลังตาม `message.autoSendMs` → ส่ง → **รอ AI ตอบจบ** → กลับไปรอฟังรอบใหม่ จนกดปุ่มเดิมเพื่อปิดหรือกด Escape ไม่เปิดไมค์เองตอนเปิดแอปและไม่ต้องกดคีย์ค้าง การรอตอบอิงสถานะ turn ของ DSH ไม่ใช่แค่รอเซิร์ฟเวอร์รับข้อความ
- ต้องอนุญาตไมโครโฟนและมีผู้ให้บริการถอดเสียงที่รองรับ audio blob พร้อมใช้งาน โหมดนี้ไม่ใช่ browser-only Web Speech และยังต้องตั้ง API key หรือเซิร์ฟเวอร์ local ตามผู้ให้บริการ
- โหมดคุยต่อเนื่องตรวจเสียงด้วยระดับความดังหลัง noise gate (amplitude detector) ไม่ใช่ Silero neural VAD จึงอาจได้รับผลจากเสียงรบกวน กดปิดหรือ Escape เพื่อหยุด; การเปลี่ยน session ก็หยุดโหมดเพื่อไม่ส่งผิดที่ เมื่อเสียโฟกัส/ซ่อนหน้า/มีเสียง AI เล่นอยู่ จะพักไมค์แล้วกลับมาฟังเมื่อพร้อม ไม่อัดเบื้องหลัง
- การเงียบไม่ปิดโหมดเอง: บัฟเฟอร์ช่วงเงียบหมุนทิ้งทุก 15 วินาทีโดยไม่ส่งเสียงไปถอดข้อความ ประโยคที่พูดต่อเนื่องยาวมากจะตัดที่ 60 วินาทีแล้วส่งตามขั้นตอนปกติ เพื่อจำกัดหน่วยความจำ
- การรอ AI หมายถึงรอ turn สิ้นสุดและไม่มีงานค้าง ไม่ใช่การรับรองว่า AI ตอบสำเร็จ: turn ที่ถูกยกเลิก/ผิดพลาดอาจกลับมาฟังคำพูดใหม่ได้ แต่ไม่ส่งหรือเล่นซ้ำข้อความเดิมอัตโนมัติ ข้อผิดพลาดการถอดเสียง/ส่งข้อความยังหยุดโหมดให้แก้ไขก่อนเริ่มใหม่
- อัปเดตแพ็กเกจผ่าน Plugins ในชื่อ `dsh-ui-thai` ไม่ต้องติดตั้งเสียง standalone กลับมา การเปลี่ยนแพ็กเกจอาจต้องเริ่ม DSH ใหม่ตามผลตัวจัดการปลั๊กอิน
- ส่วนเสียงอิง upstream 0.9.57 ใต้ MIT; แหล่งที่มาและ SHA-256 ของไฟล์อยู่ใน [PROVENANCE.json](<vendor/dsh-voice/PROVENANCE.json>) และ [LICENSE](<vendor/dsh-voice/LICENSE>)

**ขอบเขตการตรวจ:** tests ของ state machine/แพ็กเกจไม่ใช่หลักฐานว่าไมโครโฟนจริง ผู้ให้บริการจริง หรือสิทธิ์ไมค์ของทุกเบราว์เซอร์ใช้งานสำเร็จ ต้องทดสอบการพูดจริงหลังติดตั้งบนเครื่องเป้าหมาย

### หน้าตั้งค่าเสียงแบบย่อ

หน้า Voice เหลือการตั้งค่าหลักสำหรับ API แบบ OpenAI-compatible:

1. **base_url** — URL ราก เช่น `https://api.openai.com/v1` หรือเซิร์ฟเวอร์ในเครื่องที่รองรับ API รูปแบบเดียวกัน
2. **api_key** — เก็บในระบบ credentials ของ DSH ไม่ใส่ค่าลับใน config และไม่ส่งค่าลับกลับมาแสดง การปล่อยช่องว่างคง key เดิม; ใช้ตัวเลือกลบเมื่อต้องการลบโดยตั้งใจ
3. **models** — กดโหลดโมเดลเพื่อเรียก `/models` จริงแล้วเลือก ID การโหลดรายการไม่ใช่การรับรองว่าทุกโมเดลรองรับเสียง; โมเดลที่เลือกต้องใช้กับ `/audio/transcriptions` ได้
4. **ปุ่มลัด** — จับปุ่มหรือคีย์ผสม และล้างเพื่อปิดปุ่มลัดได้
5. **ปุ่มในช่องแชต** — แสดง/ซ่อนพิมพ์ด้วยเสียง, ข้อความเสียง, เลือกโหมด และสนทนาแบบไม่กดปุ่ม

กดบันทึกจึงเปลี่ยนการตั้งค่าจริง การบันทึก API/model ใช้กับทั้งพิมพ์ด้วยเสียงและข้อความเสียง ไม่เริ่มไมโครโฟนเอง การเปลี่ยนปลายทางจะไม่ส่ง key ที่บันทึกไว้อย่างเงียบ ๆ ไปยังปลายทางอื่น หาก URL เปลี่ยนให้ระบุ key สำหรับปลายทางใหม่ หรือใช้แบบไม่ต้องยืนยันตัวตนตามที่เซิร์ฟเวอร์รองรับ

- ตัวเลือกภาพ onboarding และภาษาภายในตัวแสดงสเปรดชีตคงเป็น `en` เนื่องจากยังไม่ได้ยืนยันว่ามีทรัพยากรภาษาไทยสำหรับตัวแสดงเหล่านั้น
- ชื่อผลิตภัณฑ์ โมเดล URL รหัส API และคำสั่งคงเดิมตามหน้าที่ ข้อความสนทนาและโค้ดของผู้ใช้ไม่ถูกแปล

English fallback มีไว้รองรับคีย์ใหม่หรือคีย์ที่ไม่มีคำแปล ไม่ถือว่าเป็นการแปลครบ การแก้ส่วนที่ใช้ระบบภาษาแยกต้องแก้ปลั๊กอินเจ้าของ ไม่ใช่เพิ่มคีย์ในแพ็กนี้อย่างเดียว

## พัฒนาและทดสอบ

ใช้ Node.js 24 ขึ้นไป ไม่ต้องติดตั้ง dependency สำหรับ build และ unit tests

```sh
npm run build
npm run check
npm test
node --check bundle-client.js
```

- [translations](<translations/>) เป็นคำแปลไทยแยกตามหมวด
- [sources/en.json](<sources/en.json>) เป็นต้นฉบับภาษาอังกฤษ 58 หมวดแรก
- [sources/previews-en.json](<sources/previews-en.json>) เก็บอีก 8 หมวดพร้อมหลักฐานต้นฉบับแบบพาธภายในแพ็กเกจ
- [sources/codex-en.json](<sources/codex-en.json>) เก็บต้นฉบับส่วน Codex ที่ใช้ในแพ็กนี้
- [tools/build.mjs](<tools/build.mjs>) ตรวจคีย์และตัวแปรซ้ำ/ตกหล่น แล้วสร้างไฟล์ client แบบเรียงลำดับแน่นอน
- [tests/pack.test.mjs](<tests/pack.test.mjs>) ตรวจการลงทะเบียน ถอนทรัพยากร เปิดซ้ำ และย้อนกลับเมื่อการลงทะเบียนล้มเหลว

### อัปเดตซอร์สเสียงที่ฝังไว้ (ผู้ดูแล)

1. เตรียม upstream worktree ที่ตรวจทานแล้วใน `dsh-voice/` (โฟลเดอร์นี้ถูก ignore; ห้ามเพิ่ม nested `.git` เข้าแพ็ก)
2. ประสานงานให้ทุกผู้แก้หยุดเขียนก่อน แล้วรัน `npm run vendor:voice` เพื่อคัดลอกเฉพาะ runtime, locale, README และ license; สคริปต์ไม่แก้ worktree ต้นทาง
3. `npm run build` สร้าง client เดียวจาก [client.js](<client.js>) และ [vendor/dsh-voice/lib/client.js](<vendor/dsh-voice/lib/client.js>) โดยเปลี่ยนเฉพาะ plugin-manager row key ไม่เปลี่ยน namespace การตั้งค่า
4. รัน `npm test`, `npm run check`, `npm pack --dry-run --json` และตรวจ diff/provenance ก่อนเผยแพร่ อย่ารัน upstream generator หลังแก้ built client โดยไม่ย้ายการแก้ไปยัง upstream source ก่อน
5. Commit snapshot ใน `vendor/` พร้อม [bundle-client.js](<bundle-client.js>) เพื่อให้ผู้ใช้ดาวน์โหลดและติดตั้งได้โดยไม่ build และไม่ต้องดาวน์โหลดอีกแพ็กเกจ

### การทดสอบกับ DSH ที่ติดตั้งจริง

รันจาก PowerShell ของ DSH Desktop ซึ่งมี `DSH_NODE_EXECUTABLE` และ `DSH_INSTALL_DIR`

```powershell
./tools/electron.ps1 tools/test-real-locale.cjs
./tools/electron.ps1 tools/test-voice-host.cjs
```

การทดสอบภาษาใช้ LocaleRuntime จาก DSH ที่ติดตั้งจริง ตรวจข้อความและการแทนตัวแปรครบ 3,965 คีย์ โดยแทนเฉพาะ UI imports ที่ไม่ได้ใช้ด้วย stub ไม่ใช่การทดสอบเบราว์เซอร์ ส่วน Host smoke test ใช้ `createRuntimeResolution` และ `PluginPackages` ของ DSH จริงเพื่อยืนยันการ import backend พร้อม dependencies จาก linked workspace ที่ไม่มี `node_modules` โดยไม่เรียก apply ไม่เปิดไมค์ และไม่แก้โปรไฟล์

การตรวจแพ็กเกจประกอบด้วย unit tests, การสร้างซ้ำ, syntax, tarball และ LocaleRuntime จริง ส่วน Hub ต้องทดสอบร่วมกับแพ็กหลักทั้งสองลำดับการโหลดและการเปิด/ปิด เพื่อไม่ให้ Hub ลงทะเบียนทับภาษาไทย ผลทดสอบระดับนี้ไม่ใช่การตรวจเบราว์เซอร์ครบวงจร ยังไม่ได้ยืนยันการแสดงผลทุกหน้า การตัดบรรทัด ไอคอน หรือการคงค่าภาษาหลังรีเฟรชและเริ่มแอปใหม่ด้วยการควบคุม GUI
